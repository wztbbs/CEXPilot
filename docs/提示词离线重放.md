# 提示词离线重放

`scripts/replay_trace.py` 用旧 trace 的实际输入和本地当前提示词，直接请求一次模型。无需部署，不调用 `/api/ask`，不创建会话、监控或线上 trace，也不执行行情工具。Python 标准库即可运行。

默认重放 **planner 首轮**，便于验证“改完提示词，第一次响应是否符合预期”，不会拿旧 trace 最后修复成功的那一轮当作首次输入，也不会自动重试或继续调用回答模块。

## 使用

密钥只从环境变量读取，不支持命令行明文 key，也没有任何硬编码默认密钥。可以复用服务器配置中的 `LLM_NORMAL_API_KEY`；请在自己终端或秘密管理工具中设置，勿粘到仓库或测试报告。

已设置该环境变量后，在仓库目录运行：

```bash
python3 scripts/replay_trace.py 12c735ec-2ff9-43d7-9e81-77a4ba91f01b
```

只有 traceId 是必需的命令行参数，key 来自环境变量。脚本先只读拉取 `GET /api/trace_detail/{traceId}`，再直调模型；修改本地 `src/main/resources/prompts/dag_planner.txt` 后重新运行即可比较。

模型选择优先级为 `--model` > `LLM_NORMAL_MODEL` > 所选 trace 调用实际记录的模型。默认 LLM base URL 为 `LLM_NORMAL_BASE_URL`，未设置时使用 `https://tokenhub-intl.tencentmaas.com/v1`；trace 站点默认 `https://cex.hrscrm.net`，可由 `CEXPILOT_BASE` 覆盖。切换服务商时请设置相应 base URL、模型与该服务商的 key。

| 配置 | 历史 trace 是否记录 | 默认行为 |
| --- | --- | --- |
| `LLM_NORMAL_BASE_URL` | 否 | 腾讯端点，环境变量或 `--base-url` 可覆盖 |
| `LLM_NORMAL_API_KEY` | 否，也不应记录 | 必须配置环境变量，无默认密钥 |
| `LLM_NORMAL_MODEL` | 是，LLM_CALL 中有实际模型 | 不配置时沿用 trace 模型；环境变量或 `--model` 可覆盖 |

```bash
# 使用另一个密钥环境变量、端点或模型；这里传的是变量名，不是密钥本身。
python3 scripts/replay_trace.py <traceId> --api-key-env MY_LLM_KEY \
  --base-url https://example.com/v1 --model your-model

# 只组装请求、保存新旧提示词差异；不要求 key，不请求模型。
# 没有 --trace-file 时仍会只读获取 trace。
python3 scripts/replay_trace.py <traceId> --dry-run

# 使用已保存的完整 trace，完全本地检查，不发任何网络请求。
python3 scripts/replay_trace.py <traceId> --trace-file /tmp/trace.json --dry-run

# 检查回答提示词：复用当时的 FACTS 和时间，不重新查询行情。
python3 scripts/replay_trace.py <traceId> --stage answer

# 重放路由、监控规划或 planner 的第二次调用。
python3 scripts/replay_trace.py <traceId> --stage router
python3 scripts/replay_trace.py <traceId> --stage monitor
python3 scripts/replay_trace.py <traceId> --attempt 2

# 不修改正式模板，临时指定一份候选模板。
python3 scripts/replay_trace.py <traceId> --prompt /tmp/dag_planner-candidate.txt
```

## 保留什么、替换什么

脚本保留 trace 的完整消息、问题、历史上下文、原指标/算子目录、查询规模限制、原时间基准，以及已记录的模型、temperature、seed 和思考模式，替换对应阶段的本地提示词模板。输出约束复用历史 response_format，参数操作协议迁移按下面的规则同步。`answer` 阶段还保留原 FACTS/QUERY_STATUS；后续修复轮也保留当时收到的错误反馈和旧模型输出，单独重放该轮。

参数操作协议升级后，planner 的 JSON Schema 会同步本地 `condition_updates` 字段、移除旧 `explicit_conditions` 字段，避免旧 Schema 与新提示词矛盾；历史 plan 内的指标/算子 Schema 保持不变。结果中 `parameter_schema_updated` 标明是否发生了此替换。需要严格复现旧 Schema 时加 `--keep-trace-schema`，并使用对应旧协议的模板；非 json_schema 模式不受影响。

| 阶段 | 本地模板 |
| --- | --- |
| planner（默认） | `dag_planner.txt`；若该次调用实际为澄清修复，则自动匹配 `clarification_repair.txt` |
| router | `intent_router.txt` |
| answer | `agent_system.txt` |
| monitor | `monitor_planner.txt` |

恢复插值的方式：读取 trace 的 `build_commit`，用本地 `git show` 取得当时模板，与 trace 的 system 消息**完整匹配**，提取目录、上下文等实际变量，再填入当前模板。`{{m1.binance.value}}` 等 DAG 引用保持字面值，不会被误当作模板变量替换。脚本不会自动拉 Git 历史。

若部署来自外部提示词、缺少旧 commit，或旧 trace 没有完整 messages，不能凭 question 猜造原始输入。旧 commit 不可用但本地模板能完整匹配旧 system 消息时允许重放；否则需提供部署时的原始模板：

```bash
python3 scripts/replay_trace.py <traceId> --old-template /tmp/deployed-dag_planner.txt
```

若本地新模板与原 system 消息相同，脚本会明确提示“相同输入下再次采样”。模型输出存在波动，单次符合预期不代表稳定通过。

## 结果与边界

终端展示旧响应、新响应、耗时、finish_reason 和 token usage。每次以唯一文件名保存 JSON 到 `importants/回归测试/prompt-replay/`，包含新请求、提示词差异、旧响应与新响应，便于人工对照。调用失败也保存请求和安全错误摘要，不自动重试。

结果不包含 Authorization；文件创建权限为 `0600`，对当前 key 的回显会脱敏，HTTP 错误不打印可能包含凭据的响应体。报告包含真实问题、上下文和工具事实，应按实际数据访问权限保管。

本脚本只观察 LLM 输出；`json_parse=VALID_JSON` 仅表示响应可解析，**不表示 Java 计划校验通过或业务回答正确**。它不会执行原校验器、工具、程序修复或完整问答链路。本地指标目录、算子实现或校验器修改也不会替换旧 trace 中的目录/事实；这些变更仍需相应单测与端到端验证。

## 离线测试

```bash
python3 -m unittest discover -s scripts/tests -p test_replay_trace.py -v
```

测试使用构造 trace 和假模型响应，不访问线上或消耗模型额度。新增或修改脚本后不自动执行真实模型请求，实际运行由用户明确发起。
