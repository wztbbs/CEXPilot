# 首页、会话导航与监控记录

本次复用现有表结构，无数据库迁移。会话和任务仍按当前浏览器的 `cexpilot_uid` 隔离，不支持凭邮箱跨设备认领。

## 首页推荐问题

配置为 `src/main/resources/home-suggestions.yml`，包含 1 条固定的功能介绍和 15 条行情/监控问题，覆盖当前快照、自然日/滚动窗口、聚合与跨所比较、主动监控。其中新增 5 条现货相关问题：币安 BTC 最新价、OKX ETH 24 小时涨跌幅、现货窗口均价、跨所现货成交额比较，以及同所永续与现货价差。现货候选沿用现有类别和随机推荐规则。`id` 唯一，`category` 为展示分组，`query` 为填入输入框的完整文本。`pinned: true` 固定在前；`answer` 配置固定回复，两者可独立使用。

`HomeSuggestions` 在服务启动时加载只读快照。修改文件不会热更新，重启后生效。支持通过 `HOME_SUGGESTIONS_LOCATION=file:/path/queries.yml` 使用外部文件；默认读取打包的 classpath 文件。配置缺失、空列表、字段缺失或重复 ID 会阻止启动并报告配置错误。

`GET /api/home/suggestions` 返回最多 4 条，每条含 `id/category/query/pinned`，不返回答案。固定项按 YAML 顺序排在前面，其余从普通项随机补足，尽量覆盖不同类别、不重复选择。当前始终第一条为“你能实现哪些功能？”，另选 3 条。接口不调用模型和交易所，不读取数据库；返回 `Cache-Control: no-store`。

发送完整的固定问题时，`/api/ask` 和 `/api/ask/stream` 直接使用 YAML 中的答案，不调用 router、planner、answer 模型或交易所。仅容忍首尾空白及末尾问号/句号等标点；编辑成其他问题后走正常模型链路，结构化澄清提交也走原有流程。固定回复仍保存会话历史和 trace（`STATIC_REPLY`，携带配置 ID 与答案），调用次数、token 和费用均为 0；不创建 `LLM_CALL` 事件，不纳入调用级缓存命中率。已有查询任务、待澄清信息与监控焦点保持原状，之后可以继续原任务。答案修改后同样重启生效，新增能力时需同步维护此说明。

页面每次加载只获取一次推荐问题，首次访问及新建会话空白页展示。同一页面点击输入或切换会话不会重新抽取。点击只填入文本，可以编辑后发送；监控仍须确认条件与邮箱后才启用。资金费率推荐使用最近 N 期，不冒充时间窗口查询。

## 会话接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/conversations?search=&limit=30&offset=0` | 当前访客的非空会话，按最近活跃时间排序。标题搜索为字面子串，limit 限 1～100，offset 最低 0。返回数组，每项含 conversationId、title、createdAt、lastActiveAt。无 cookie 返回空数组。 |
| `POST /api/conversations` | JSON 请求体 `{}`，显式创建空会话，首次访问时设置访客 cookie。返回 conversationId、空 parentTurnId 和 messages。 |
| `GET /api/conversation/{id}` | 校验访客归属后返回消息及 parentTurnId。其他访客、无 cookie 或不存在均返回 404。 |
| `GET /api/conversation/latest` | 保留旧接口，页面首次加载恢复最近会话。 |

新建按钮调用独立创建接口，随后使用返回的 ID 发问。未发送消息的空会话不进入历史列表；首条消息会填入 `conversation.title`（问题前 60 字，超出加省略号），不调用模型生成标题。旧客户端不传 ID 时仍复用最近会话。带已有 ID 发问时也校验访客归属。

切换会话恢复该会话自己的 parentTurnId、消息和澄清表单；进行中的请求完成前不允许切换。草稿在当前页面内按会话分别保留，刷新不持久化。新建会话不清除原会话或停止监控。刷新上下文冲突时读取当前会话，不跳到其他最近会话。

## 监控视图

复用 `/api/monitor-flow/rules`、`/rules/{id}`、`/rules/{id}/executions` 和确认/停止接口。

- 卡片补充 `createdAt`、`updatedAt`、`sourceConversationId`、`nextCheckAt`（存在时）、`latestEvaluation`。
- 执行记录保留原有数组和字段，补充 `evaluationId`、`errorCode`、`evidence`、`notifications[]`。通过 `(rule_id, rule_version, scheduled_at)` 关联正确的判定，通过 evaluation_id 关联通知。通知批量查询，避免对每条记录单独请求数据库。
- 通知项含 status、simulated、sentAt（存在时）；模拟发送明确显示未发送真实邮件。
- 页面展示监控中、待确认、已停止的任务；待确认详情继续复用原有邮箱绑定、确认/取消卡片。
- 详情默认显示最近 5 次，可翻阅接口返回的最近 100 次。历史依据仍受现有清理策略限制，不承诺无限保留。
- 判定与通知分开：MATCH 是命中，不代表已生成通知；连续命中次数和提醒复位规则仍生效。NO_MATCH 是未命中；UNKNOWN 是无法判定；FAILED 是未完成；PENDING/RUNNING/CANCELLED 分别展示等待检查/检查中/已取消。
- 可展开记录查看实际值、阈值、数据截止时间、规则版本、尝试次数及通知。原始数据在折叠区域中提供。
- 所有页面文本按 DOM textContent 展示；时间按当前设备时区显示。手机使用侧栏抽屉，支持遮罩及 Escape 关闭。

## 本地验证

先执行 `mvn test-compile`，再运行相关定向测试。浏览器协议测试不访问线上系统：

```bash
node --test src/test/js/context-parent.test.cjs src/test/js/monitor-confirmation.test.cjs
# 使用已安装 Playwright 的 Node 环境，可通过 NODE_PATH 指向对应 node_modules。
node src/test/browser/home-shell.cjs
```

浏览器测试使用本地静态页面和假 API，覆盖推荐填入但不自动发送、历史恢复、草稿保留、独立会话父轮次、监控判定/通知及手机布局。推荐问题尚未逐条做真实模型端到端验收；线上回归脚本仅在用户明确要求执行时运行。
