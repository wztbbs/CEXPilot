# 聚合指标与确定性计算

当前系统有两层计算：Provider 从完整市场数据中产生成品指标；CalculationTool 对指标事实、序列或用户明确给出的常量执行通用运算。模型负责选择所需指标、算子与方向，代码负责取得操作数并计算，Answer 只组织已有结果。

本文按当前 `metrics / calculations` 协议描述，不使用文章中的旧行情 Tool 取数计划。

## 1. 成品指标与通用算子的分工

| 需求 | 当前推荐计划 | 原因 |
| --- | --- | --- |
| 昨日成交额 | trade.turnover / range_statistic | Provider 已按完整 K 线累计真实成交额 |
| 昨日涨跌幅 | price.change_pct / range_statistic | 末收盘相对首开盘，不是逐根涨跌幅求和 |
| 主动买成交量占比 | taker.buy_ratio / range_statistic | 代码按买卖量合计计算，不是各周期占比的均值 |
| 两所成交额谁大 | 两个同口径指标 + compare | 取数成功不等于比较结论已产生 |
| 两所成交额差多少 | 两个同口径指标 + difference | 明确 left - right 的方向 |
| N 期费率均值 | funding.rate_settled / recent_n + avg | 原样本集的等权平均 |
| 昨日每小时收盘价最大值及时间 | price.close / time_series / 1h + max | 与昨日最高成交价 price.high 是不同口径 |

### 1.1 Provider 内部的确定性公式

以下由 [MarketCalculator](../src/main/java/com/cexpilot/market/MarketCalculator.java) 及各 Selector / Provider 实现，调用方负责数据已通过覆盖核对：

| 指标 | 计算口径 |
| --- | --- |
| price.open / close | 第一根 K 线 open / 最后一根 close |
| price.high / low | 所有参与 K 线 high 的最大值 / low 的最小值 |
| price.change_pct | `(末 close - 首 open) / 首 open × 100` |
| trade.volume | 基础币成交量逐根求和 |
| trade.turnover | 逐根真实 quoteVolume 求和，缺成交额不改用量 × 现价 |
| oi.start / end / change | 首点 / 末点 / 末点减首点 |
| oi.change_pct | `(末点 - 首点) / 首点 × 100` |
| oi.max / min | 采样点最大 / 最小数量，不表示采样之间的真实连续极值 |
| taker.buy_ratio | 区间买量合计 /（买量合计 + 卖量合计） |
| orderbook.spread | 当前卖一减买一 |
| orderbook.imbalance | 实际可用档位、最多 10 档买量合计 / 卖量合计，可大于 1 |

标记/指数价格的区间 OHLC 与涨跌幅使用对应价格 K 线，不含成交量。官方 24h 指标来自交易所快照，不用上述自然日公式替代。

## 2. 算子执行链

```text
LogicalPlan.calculations[{id,operator,input}]
  → MetricPlanCompiler：输入预检、逻辑引用改写、依赖推导
  → PlanValidator：结构与输出字段契约校验
  → DagExecutor：等待依赖成功
  → MetricCalculationContext.validate：单位与年化来源规则
  → CalculationTool.validateSource：完整性校验
  → ReferenceResolver：字段引用替换为真实数值或集合
  → ToolRegistry.prepareArguments / CalculationTool.execute
  → 执行期 validateArguments → calculate
  → MetricCalculationContext.attach：单位与去重来源传播
  → TOOL_CALL 事件 + evidence → Answer
```

来源检查发生在丢弃元数据、提取裸数之前。不能先得到 value 再检查完整性，否则会失去“这个数来自哪个样本集”的信息。

## 3. input 与引用协议

逻辑计算节点只有 id、operator、input；物理节点由编译器包成 `args={input:...}`，不需要模型再填 args 或 depends_on。

### 3.1 集合输入：avg / sum / min / max

多个标量使用 values：

```json
{"id":"c1","operator":"avg","input":{"kind":"values","values":["{{m1.binance.value}}","{{m1.okx.value}}"]}}
```

对标准指标 samples 的 value 字段计算使用 field：

```json
{"id":"c1","operator":"avg","input":{"kind":"field","collection":"{{m1.binance.samples}}","field":"value"}}
```

[Series](../src/main/java/com/cexpilot/calculation/Series.java) 也支持已有二维表的 columns 解析，但当前指标主链输出对象数组，**不传 columns**。field 是非空字段名，不接受嵌套路径或动态引用；集合最多 10000 个元素，非空，每个参与值都必须有效，不能自动跳过 null、缺失或非法行。

### 3.2 二元输入

```json
{"id":"c1","operator":"difference","input":{"left":"{{m1.binance.value}}","right":"{{m1.okx.value}}"}}
```

compare / difference / ratio 使用 left、right；relative_change 使用 current、baseline，字段不能混用。集合、二元与年化输入都不允许无关取数参数。

行情数值必须使用事实引用，不能让模型填记忆中的现价；用户本轮明确给出的常量可以填写。引用是完整字符串，不接受 `{{m1.binance.value}}+10` 或带单位的数值字符串。

## 4. 九个算子契约

| operator | input | 核心输出 / 规则 |
| --- | --- | --- |
| avg | values 或 field 集合 | value、count、method=equal_weight_arithmetic_mean |
| sum | values 或 field 集合 | value、count、method=arithmetic_sum，精确加总 |
| min / max | values 或 field 集合 | value、count、index；field 模式附原始 item；并列取首个 |
| compare | left、right | relation=greater / less / equal；value 为 1 / -1 / 0 的字符串，精确比较 |
| difference | left、right | value=left-right，保留符号，value_unit=same_as_inputs |
| ratio | left、right | value=left/right，percent=value×100，right 必须大于 0 |
| relative_change | current、baseline | value=(current-baseline)/baseline，percent=value×100，baseline 必须大于 0 |
| annualize | basis、method、rate、rate_unit、period；可选 year_days | value 比例、percent 百分数及方法、周期、公式、假设 |

min/max.index 是输入集合的 0 基位置；item 是实际命中行，可用于说明时间，不能因首个命中就声称极值唯一。

### 4.1 差值、倍数、变化率不能互换

构造数值 A=120、B=100 时，difference 输出 20，ratio 输出 1.2（percent=120），relative_change 输出 0.2（percent=20）。它们分别回答“多多少”“是多少倍”“比基准增长百分之多少”。这是代码契约示例，不是市场数据。

percent 指标 A=3、B=2 做 difference 得到 1，回答应为 1 个百分点；不能说增长 1%。ratio / relative_change 返回的 percent 已乘 100，Answer 直接引用后加 `%`，不能再次换算。对负费率基准做 relative_change 会失败，不能交换操作数或取绝对值绕过。

## 5. 精度与数值校验

[CalculationTool](../src/main/java/com/cexpilot/calculation/CalculationTool.java) 用 BigDecimal 解析 JSON 数字或无单位十进制字符串，允许科学计数法，但不执行表达式。

- 拒绝 null、布尔值、百分号、货币单位、千分位逗号、NaN / Infinity。
- 原始数值文本最长 256 字符；最多 100 位有效数字，scale 绝对值不超过 1000。
- avg、ratio、relative_change 的除法使用 DECIMAL128：34 位有效数字，HALF_EVEN。
- sum、difference 直接做精确加减；min/max/compare 用 BigDecimal.compareTo，不设近似相等阈值。
- 数值计算结果用去尾零的十进制字符串输出，可继续被下游算子引用；count、index 等仍为整数。

**DECIMAL128 是通用算子的精度策略，不是所有市场指标的统一精度。** Provider / MarketCalculator 的成品指标仍有各自舍入规则，例如 OI 投影保留 8 位小数、盘口不平衡度除法保留 4 位。算子不能恢复上游已经舍入掉的位数。

## 6. 完整性、单位与来源传播

### 6.1 什么时候拒绝计算

依赖节点 `ok=false` 时，执行器把后续依赖节点标记为 `skipped: 上游节点失败`。上游 ok=true 时仍检查：

```text
coverage.range_complete 存在且非 true → 拒绝
sample_complete 存在且非 true        → 拒绝
complete 存在且非 true               → 拒绝
statistics_omitted 非 null           → 拒绝
```

完整性标志不是布尔类型也会失败。序列仅取齐 8 期而请求 10 期时，不对这 8 期产出请求口径的 avg；不能在 Answer 补算。路径本身合法但 value / period_seconds 不存在时，也会在执行期失败。

### 6.2 单位检查的范围

[MetricCalculationContext](../src/main/java/com/cexpilot/metric/MetricCalculationContext.java) 从已识别的 value、samples、样本 value、percent、周期秒数引用提取单位。avg / sum / min / max / compare / difference / ratio / relative_change 若出现多个不同单位则拒绝，例如 BTC 基础币量与 ETH 基础币量、percent 与 ratio 不能直接混算。

该检查不是完整的业务量纲证明器：用户常量没有上游单位，所有任意路径也未必能被识别；同为 USDT 可能对应不同窗口、不同指标、不同产品。Planner 和 Answer 仍需要核对业务口径，不能把“算子成功”解释为比较一定有效。

### 6.3 多层计算的来源

attach() 将直接指标的身份、品种、单位、窗口、coverage、粒度、目录版本及费率样本语义复制到 metric_sources；依赖其他计算时继续继承其来源，并按原物理节点 ID 去重。avg / sum / min / max / difference 有唯一已识别单位时保留该单位，ratio / relative_change / annualize 标为 ratio。

metric_sources 是供后续语义说明和排查的元信息，不能证明所有公式正确。当前复制字段集合不包含快照 as_of；快照时间应查原指标事实，不能仅看派生结果的来源列表。

## 7. 完整计划示例：两所收盘均价之差

用户明确要求“分别计算两所 BTC 昨天 1 小时 K 线收盘价等权平均，币安减 OKX 差多少”：

```json
{
  "in_domain": true,
  "plan": {
    "metrics": [{
      "id": "m1",
      "metric": "price.close",
      "exchanges": ["binance", "okx"],
      "instrument": {"market_type":"perpetual","base":"BTC","quote":"USDT"},
      "query_shape": "time_series",
      "interval": "1h",
      "time": {"type":"calendar_period","unit":"day","offset":-1,"segment":"full","extent":"full_period"}
    }],
    "calculations": [
      {"id":"c1","operator":"avg","input":{"kind":"field","collection":"{{m1.binance.samples}}","field":"value"}},
      {"id":"c2","operator":"avg","input":{"kind":"field","collection":"{{m1.okx.samples}}","field":"value"}},
      {"id":"c3","operator":"difference","input":{"left":"{{c1.value}}","right":"{{c2.value}}"}}
    ]
  },
  "reply": null
}
```

展开后是 5 个节点、3 层：两所取数 → 两个 avg → 一个 difference。每个均值是采样收盘价的等权算术平均，不是成交均价、VWAP，也不是对所有成交的总体平均。两侧完整性独立检查，任一侧失败阻断 c3；另一侧均值仍可返回。

只要求“分别列出两所昨日收盘价”时不添加 compare；要求“谁更高”时添加 compare；要求“差多少”时才选择 difference。返回两个裸数不能充当已完成比较。

## 8. 年化

### 8.1 参数与公式

| 参数 | 约束 |
| --- | --- |
| basis | periodic_rate 单期外推；cumulative_rate 累计费率；holding_return 持有期总收益 |
| method | 必填 simple / compound；cumulative_rate 只允许 simple |
| rate / rate_unit | 必填；ratio 的 0.0001 与 percent 的 0.01 都表示 0.01% |
| period | `{value,unit}`；second / minute / hour / day；总时长 1 秒～365250 天 |
| year_days | 缺省 365，可选整数 360 / 365 / 366；不自动推断闰年 |

令 r 为统一后的比例，n=year_days×86400/period_seconds：simple=r×n，compound=(1+r)^n-1。[AnnualizeTool](../src/main/java/com/cexpilot/calculation/AnnualizeTool.java) 使用 big-math 十进制 log / exp 实现非整数幂，为极小费率增加工作精度后舍入为 DECIMAL128；年化对数增长绝对值超过 200 时拒绝。holding_return 或 compound 不接受低于 -100% 的输入，-100% 复利返回 -100%。

缺 method、basis 或周期不会静默套“惯例”。输出同时记录 input_rate、rate_ratio、period_seconds、year_days、year_days_source、annual_factor、formula、interpretation、assumption。

### 8.2 当前行情来源只开放两条路径

| 来源 | 必须匹配的 rate | basis / rate_unit | 必须匹配的 period |
| --- | --- | --- | --- |
| price.change_pct / range_statistic | 同源 value | holding_return / percent | 同一指标 observation_seconds，unit=second |
| funding.rate_settled / recent_n / count=1 | 同源 samples.0.value | periodic_rate / ratio | 同一指标 period_seconds，unit=second |

不接受成交额或价格金额年化，不接受 mark / index / oi 变化率，也不接受 avg / sum 的中间结果作为行情年化 rate。多期费率 samples.0 是最旧的一期，不能伪装最近一期；因此要求 count=1、单条且 sample_complete=true。

单期费率周期来自相邻历史结算时间，可核实才提供 period_seconds；缺周期不妨碍报告已结算费率，但不能猜 8 小时、混用其他节点周期或改引用当前周期。历史周期不能推断未来结算时间。

用户明确提供的收益率与周期常量仍可以年化，但要全部为明确常量，不混入行情周期引用。下面是逻辑计算节点的构造例子：

```json
{"id":"c1","operator":"annualize","input":{"basis":"periodic_rate","method":"simple","rate":"0.01","rate_unit":"percent","period":{"value":8,"unit":"hour"}}}
```

默认 365 天时，代码结果 value=`0.1095`，percent=`10.95`。这只是指定常量的折算，不是当前费率或未来收益。正资金费率表示多头付空头，不自动等于多头收益；复利需要披露复投假设。

`cumulative_rate` 在常量算子契约中存在，不表示当前 Planner 已能按时间窗口查询累计历史费率。目录只有 recent_n，不能把 N 期之和声称为一周累计再年化。

## 9. 观察与扩展

排查时先看 PLAN 是否安排了用户要求的最终算子，再看 TOOL_CALL 的已解析 input、输出和 error，最后核对 Answer 是否直接引用结果。若计划漏了 avg / relative_change，数据取齐也无法证明任务完成；合法计划不保证模型一定理解了正确口径。

新增算子需同步：CalculationTool 实现与规划输入 schema、`tools/<name>.yml` 注册和输出契约、指标目录 operators 业务说明、必要的单位/来源规则与 Answer 说明。新增成品指标则优先放在对应 Provider / Selector 和指标 binding 中，不必全部拆成通用算子。

相关测试：`CalculationToolTest`、`SeriesCalculationToolTest`、`PairwiseCalculationToolTest`、`AnnualizeToolTest`、`CalculationDagTest`、`MetricPlanCompilerRegressionTest`、`ToolOutputSchemaTest`，以及对应 Provider 测试。重点验证负数极值、并列、空集合、精度、正基准、单位冲突、不完整上游、多层来源与年化同源周期。先 `mvn test-compile`，仅选择直接相关测试；线上算子探针需明确执行指令。
