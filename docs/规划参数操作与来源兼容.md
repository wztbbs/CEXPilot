# 规划参数操作与来源兼容

本次将模型协议从广泛的 `explicit_conditions` 原文登记，收敛为只影响继承的 `condition_updates`。无需数据库迁移，已有任务快照和来源标识继续可读。

## 新输出协议

普通查询只返回完整 `plan`，省略 `condition_updates` 或返回 `{}`。币种、交易所、市场、指标、时间等继续由计划表达，不要求重复抄写用户原文。

只有用户本轮明确设置或恢复以下可选参数时才输出操作：`interval`、`include_unclosed`、`depth`、`settle`。参数必须适用于对应指标、市场和查询形态，能力范围仍来自指标目录。

```json
{"condition_updates":{"m1":{"interval":"set"}}}
```

`set`：计划中必须显式提供该参数值。即使值恰好等于上次自动粒度或默认深度，也表示本轮明确设置。是否为用户要求由 Planner 结合语义判断，程序检查操作结构、计划值及目录约束，不要求逐字原文凭据。

```json
{"condition_updates":{"m1":{"interval":"reset"}}}
```

`reset`：计划中省略该参数，由程序使用自动/默认值，并解除旧固定要求。JSON null 也按省略规范化；不能同时 reset 又填固定数值。无操作时继续原继承行为，不能把上次自动选择的实际执行粒度抄成固定粒度。

例：“昨天最高价，用1小时粒度” → plan.interval=`1h`、操作=`set`；“换成前天” → 继续 `1h`、不声明新操作；“改回自动粒度” → 省略 interval、操作=`reset`。

`reset` 在来源中保存为本轮 `EXPLICIT` 操作、原始要求性质 `DEFAULT`；后续能继续自动，不会把本次实际执行值重新固化。`set` 保存为 `EXPLICIT` 要求。新操作不编造 `userText`，来源轮次与任务版本仍由服务端生成。

## 旧字段兼容

模型提示词不再要求输出 `explicit_conditions`，发送给模型的 JSON Schema 也不再列出旧字段。运行时仍接受旧字段：

| 旧标注情况 | 处理 |
| --- | --- |
| 原文有效且字段适用 | 沿用旧来源语义 |
| 字段未知、不适用或指标组不存在 | 忽略标注，记录 warning |
| 原文并非本轮问题字面片段 | 来源标为未核实，不认作本轮明确条件 |
| 原文无效，忽略后会改变某个可选参数的继承 | 请求修复，提示改用 set/reset，避免静默改变用户要求 |
| 同一参数已有合法新操作 | 新操作优先，旧原文异常保留 warning，不阻止操作 |

例如“币安的比特币现在多少钱？”的旧响应即使登记了默认永续/USDT 或 `time="现在"`，也不会仅因这些辅助标注重试。计划中的真实 `time`、币种、市场、参数值等仍严格校验；snapshot 实际填了不允许的 time 不能放行。

`CONDITION_WARNING` trace 事件及服务日志记录 `code/path/message`。warning 不作为轮次失败；完整原始输出保留在原有 LLM_CALL 中。标注忽略不会删除用户澄清输入或隐藏给用户的澄清原因。

## 错误反馈

参数操作中的多个结构错误、set/reset 与计划的矛盾、适用性错误、可独立判定的继承冲突会汇总到同一修复反馈；编译失败时也附带已收集的操作错误。原有编译器和 DAG 校验器仍负责各自的计划错误集合。

汇总限于当前阶段能够可靠检测的错误；编译无法生成有效目标时，不能提前完成后续依赖这些目标的继承或事实绑定校验。不增加额外 LLM 调用来收集来源。

## 提示词重放

`replay_trace.py` 默认把 planner JSON Schema 中旧来源字段替换为本地的 `condition_updates` 协议，保留历史 plan 中的指标/算子 schema、目录、上下文与事实。否则旧 trace 的 Schema 可能禁止模型输出新操作。

`--keep-trace-schema` 可以严格保留旧 Schema，仅用于对比旧协议；这时需要选择与旧协议一致的候选提示词。脚本依然不执行 Java 校验器和工具。

## 验证

定向测试覆盖旧异常来源首轮接受、warning 可观测、操作与计划矛盾的批量反馈、固定粒度恢复自动、include_unclosed/settle/depth 恢复默认、默认数值的明确固定、无操作继承、旧原文异常但影响继承时的修复，以及原有任务/事实保护。

```bash
mvn test-compile
mvn test -Dtest=ConditionProvenanceResolverTest,DagPlannerTest,InheritanceValidatorTest,PlannerModelFallbackTest,DagRuntimeTest,MetricPlanCompilerRegressionTest,TaskPipelineTest,TaskLifecycleTest,ConversationContextServiceTest
python3 -m unittest discover -s scripts/tests -p test_replay_trace.py -v
```

测试使用固定模型响应或本地假取数，不请求真实模型和交易所；模型输出稳定性仍需明确发起重放或线上回归验证。
