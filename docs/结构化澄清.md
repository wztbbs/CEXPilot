# 自由文本澄清表单

Query Planner 缺少必要条件或无法确定含义时，返回 `needs_clarification=true`、`plan=null` 和非空 `clarify`。`task_action=CONTINUE` 仅表示接续任务。

```json
{
  "in_domain": true,
  "needs_clarification": true,
  "plan": null,
  "reply": null,
  "clarify": [
    {"key":"base","label":"币种","reason":"missing","message":"请填写要查询的币种","options":["BTC","ETH"]},
    {"key":"exchange","label":"交易所","reason":"missing","message":"请填写要比较的两家交易所","options":["币安","OKX"]}
  ]
}
```

每项必填 key、label、reason、message，可选 placeholder、hint、options、value。前端每项只有一个自由文本框，options 在旁边以“参考”展示，不是可选值枚举，不强制用户使用参考项或准确拼写。明确“两所”只表示数量，不自动指定对象；需要时由 message 追问，用户可以填写“币安和ok”。

不再让模型生成 type、min、max、minSelections、maxSelections 等控件元数据。新 schema 不包含这些属性，服务端读取旧输出及历史记录时忽略这些属性，不会因为旧 type=number 同时带 options、min 为空等问题拒绝表单。可选参考项或展示提示格式不佳时尽量忽略，不阻断必要问题。

## 原话与业务解释

用户输入“ok”“okx”“比特币”“最近十期”等原话，按原文保存，并作为下轮用户条件传给 Planner。在能唯一理解的语境中，由模型归一化为 OKX、BTC、count=10 等实际计划参数。多个对象可以写在同一条件的文本中，例如“币安和ok”；无法理解、有歧义或不支持时必须说明具体原因。

表单阶段不校验选项成员、选择数量、数值范围、日期格式，不把填写值自动认定为已验证。支持的市场/交易所、指标、时间口径、整数期数及目录范围仍由实际计划的解析、编译和执行层校验。例：“最近两百期”可以提交；若接口最多100期，生成执行计划时必须拒绝越界，并解释缺口或继续纠错，不实际查询200期。

## 补缺失、纠错与确认

- missing：尚未提供该条件。
- invalid：已提供但格式、范围或业务要求不合法；message 说明具体问题。
- confirm：有歧义或需要确认；message 说明具体待确认事项。

前端在对应文本框旁显示 message；纠错、确认时保留“上次填写”并预填原值，允许直接编辑。普通答案文本也包含原因。不能仅因字段 key 已填就隐藏澄清项；也不能把有效的已有条件反复当作缺失。value 为用户原文，模型不要自行改写回显值。

## 提交、接续与兼容

普通响应、SSE done、历史记录均提供 clarify 数组，无表单时为 []。结构化结果仍保存在已有 agent_payload_json；不新增数据库列。

前端提交同一 conversationId、当前 parentTurnId、可读 question，以及 `clarificationAnswers`（key → 原始文本）：

```json
{
  "conversationId":"...",
  "parentTurnId":"...",
  "question":"补充本轮查询条件：\n币种：比特币\n交易所：币安和ok",
  "clarificationAnswers":{"base":"比特币","exchange":"币安和ok"}
}
```

原值随任务版本保存，同 key 的新值覆盖旧值，保留其他条件。刷新恢复原文；旧的字符串澄清、控件元数据和数组快照继续可读，旧数组在文本框中以完整文字回显，新提交统一为文本。不按参考项过滤、拆分或删掉原值。过期表单、并发占用和父轮次冲突仍按现有机制处理。

## 保留与移除的校验

保留：字段 key 唯一及基本格式、标签和说明、纠错/确认原因、请求字段属于父轮次表单、基本空值和长度限制、简单 JSON 结构、只允许当前轮次提交。它们保证可展示、可绑定、可接续，不判断用户业务语义。

移除：控件类型枚举、选择框必须有 options、非选择框不得有 options、选项成员身份、选择数量及上下限、输入值的数字/日期格式或业务范围。options 只是提示，缺失、不完整或用户填写了其他表达均不阻断输入。

旧文字数组只做兼容读取及基本体积限制，重复项/别名等语义留给后续规划判断。不可传对象或嵌套结构冒充文本值。

若明确要求澄清却无有效字段，仍记录 CLARIFY_INVALID 并最多进行一次专项字段修复，修复失败记录 FAILED，不生成空表单冒充成功。这里校验的是必要的展示结构；新的专项 schema 只有简单文字字段，不再让模型绑定控件或输入限制。
