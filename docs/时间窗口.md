# 时间窗口

时间查询分为三个独立问题：用户要哪段时间、数据源能否提供这段数据、实际结果覆盖了哪里。模型只把时间表达写成 TimeSpec；代码结合固定请求时刻消解，再做能力检查、分页和覆盖核对。本文描述当前指标主链，不把底层已有但未接入的查询当成对外能力。

## 1. 执行链与关键对象

```text
AskService 固定 RequestContext(userZone, requestTime)
  → LogicalPlanParser / TimeSpecParser：JSON → TimeSpec
  → MetricProvider：选择查询服务与粒度策略
  → TimeRangeResolver：TimeSpec → requested TimeRange
  → SeriesQueryPolicy：能力检查、网格对齐 → effective TimeRange
  → Source：接口参数、分页、去重、排序
  → SeriesCoverageValidator：预期时间点与实际位置核对
  → Provider：样本投影 / 完整区间统计 / Omitted
  → MetricResultJson：窗口、实际范围与覆盖状态
```

| 对象 | 含义 |
| --- | --- |
| [RequestContext](../src/main/java/com/cexpilot/runtime/RequestContext.java) | 一次请求固定的绝对时刻和用户时区 |
| [TimeSpec](../src/main/java/com/cexpilot/time/TimeSpec.java) | 用户时间意图，不含模型推算的毫秒边界 |
| [TimeRange](../src/main/java/com/cexpilot/time/TimeRange.java) | `[startInclusive,endExclusive)`，保留渲染时区 |
| requested_range | TimeSpec 按固定时间与时区消解后的原始目标区间 |
| effective_range | 取数与覆盖检查使用的网格对齐区间；相同则 JSON 可省略 |
| actual_range | 成功 Scalar 实际参与统计的首末数据边界 |
| coverage | 数据位置、完结状态、分页中止与实际截止时间 |

## 2. “现在”与时区

`AskService` 在规划前从注入的 Clock 读取一次 `clock.instant()`。DagRuntime 补齐缺省值后，将同一 RequestContext 传给所有 Provider、时间解析和 Answer；规划重试、分页耗时、回答跨午夜都不改变本轮相对时间含义。

时区优先级是：**TimeSpec.timezone → 请求 timezone → 产品默认 +08:00**，不使用应用服务器的本地时区。用户请求建议填写 IANA 标识，例如 Asia/Shanghai、America/New_York。默认时区不能解释为已知用户所在地。

自然周期按该时区的日历边界计算；滚动窗口按固定 Duration 从 Instant 回溯。自然日受夏令时影响可能不是 24 小时，而 rolling_window 的 day 固定为 24 小时，两者不能混用。

Answer 的 TIME_CONTEXT 包含 request_time_utc、request_time_local、current_date、timezone、timezone_source。时间含义以各查询结果的 requested_range 为准；查询自身指定其他时区时，回答不能用请求默认时区覆盖它。

## 3. 四种 TimeSpec

解析入口 [TimeSpecParser](../src/main/java/com/cexpilot/time/TimeSpecParser.java) 拒绝未知字段、非法类型和枚举，不把错误参数静默换成默认窗口。各类型必填项如下；timezone 可省略或为 null，其余按契约填写。

### 3.1 自然周期 calendar_period

```json
{"type":"calendar_period","unit":"day","offset":-1,"segment":"afternoon","extent":"full_period"}
```

对应“昨天下午”。unit 支持 day / week / month / quarter / year。先取请求日期所在周期起点，再按 offset 平移；offset=-1 表示上一个周期。周从周一开始，季度为自然季度。

| segment | 当地时间范围 |
| --- | --- |
| full | 当天 00:00 → 次日 00:00 |
| early_morning | 00:00 → 06:00 |
| morning | 06:00 → 12:00 |
| afternoon | 12:00 → 18:00 |
| evening | 18:00 → 次日 00:00 |

非 full 时段只允许 unit=day。extent=full_period 表示整个周期；extent=to_request_time 只允许 offset=0 且 segment=full。例如“本月至今”从当地月初到 requestTime；“今天全天”终点为次日午夜，白天请求时有未来部分，不能当成“今天截至现在”。

### 3.2 滚动窗口 rolling_window

```json
{"type":"rolling_window","duration":{"value":6,"unit":"hour"}}
```

对应过去 6 小时，终点严格为 requestTime，不先取整到小时边界。duration.value 为正整数，unit 支持 second / minute / hour / day / week，不接受 month / year 这类非固定时长。

### 3.3 相对日期钟点 relative_day_range

```json
{"type":"relative_day_range","start":{"day_offset":-1,"time":"22:00:00"},"end":{"day_offset":0,"time":"02:00:00"}}
```

对应“昨晚 22 点到今天凌晨 2 点”。起止日期分别按请求当地日期加 day_offset 生成；跨天要显式改变 end.day_offset，不能把同一天的 02:00 视为自动跨天。end 必须晚于 start。

### 3.4 绝对日期 absolute_range

```json
{"type":"absolute_range","start":{"year":2026,"month":9,"day":1},"end":{"year":2026,"month":9,"day":3},"end_mode":"inclusive_date"}
```

对应包含 9 月 1、2、3 日整天，即 `[09-01 00:00,09-04 00:00)`。year 可省略，time 可选；`inclusive_date` 只用于 end 未指定 time，`exclusive` 直接把 end 作为右开边界。

省略年份由 [TimeRangeResolver](../src/main/java/com/cexpilot/time/TimeRangeResolver.java) 确定性处理：start 先用请求年份，若该月日在请求当地日期之后，取上一年；end 未填 year 时从 start 的年份开始，必要时向后顺推直到结束边界晚于起点。这样可表达“12 月 30 日到 1 月 2 日”的跨年范围。显式年份不自动修正；无效日期如 2 月 30 日直接失败。

## 4. 左闭右开与网格对齐

内部时间窗口和 Source 的物理取数契约默认采用 `[start,end)`，边界点只属于一侧。例如昨天和今天在当地午夜连接，不会重复计算同一根 K 线。OI 端点统计另有包含逻辑终点的选样语义，见下文；不能把时间窗口的表示直接当作所有指标的选样规则。

K 线及规则采样源只能按其时间网格提供数据。[SeriesQueryPolicy.align()](../src/main/java/com/cexpilot/market/series/SeriesQueryPolicy.java) 使用 epoch 毫秒网格：

```text
alignedStart = floor(start / intervalMs) * intervalMs
alignedEnd   = ceil(end / intervalMs) * intervalMs
```

范围向两端外扩，不能用粗粒度假装精确回答任意秒级区间。网格锚定的是绝对时间，不能假定所有时区的自然日都与粗粒度网格吻合。

### OI 序列与端点统计

`OiQueryMode` 区分两种用途：

| 用途 | 选样与校验 |
| --- | --- |
| `INTERVAL_SAMPLES`：序列、MIN/MAX | 保持 `[start,end)`；13:00→14:00、5m 使用 13:00…13:55 的 12 点 |
| `BOUNDARY_VALUES`：START/END/CHANGE/CHANGE_PCT | `[start,end]`；同一窗口使用 13:00…14:00 的 13 点，右端点也必须存在 |

Source 接口不变，Service 对端点统计将物理上界多取 1ms；这 1ms 不进入 `requested_range`、`effective_range`、未来判断或观测时长。覆盖核对包含右端点，预算也包含新增的第 13 点。首版端点统计继续要求全段采样完整，中间缺点也不输出统计值。

端点统计的滚动窗口整体平移到最近已到达采样网格：14:03 查询最近一小时、5m，`requested_range` 是 13:03→14:03，`effective_range` 和 `selection_range` 是 13:00→14:00，保持一小时。明确日期范围不自动平移或外扩；所选粒度无法精确表达端点时返回 `statistics_omitted`。未指定粒度的端点统计从支持的细粒度开始选，通常为 5m，超预算时选可表达同一窗口时长的较粗粒度；显式粒度不覆盖。序列和极值缺省仍为 1h。

14:00 尚未发布时，不能用 13:55 冒充终点，结果为不完整并省略 value。变化量/率至少需要两个不同时刻的端点；零基数变化率也省略 value。

OI 统计使用 `MetricResult.SampledScalar`，`actual_range.start_inclusive/end_inclusive`、`start_sample_at/end_sample_at` 明确记录实际采样时刻，`observation_seconds` 为两采样时刻之差。START/END 只对应一个时刻，单点极值也可返回值，此时观测时长为 0；不能因此推断区间变化为零。K 线等周期指标的 `Scalar` 和 `actual_range.end_exclusive` 保持原契约。

下面是固定请求时刻 `2026-10-12 15:21:13+08:00`、过去 6 小时、5m、默认排除未收盘数据的**构造示例**：

| 层次 | 范围 / 时间 |
| --- | --- |
| requested_range | 09:21:13 → 15:21:13 |
| effective_range | 09:20:00 → 15:25:00 |
| 已收盘 K 线起点 | 09:20、09:25、…、15:15 |
| actual_range | 09:20:00 → 15:20:00 |
| coverage.covered_until | 15:20:00 |

此时 15:20 开盘的 K 线尚未收盘，剔除后如果已收盘部分无缺口，`range_complete` **仍可为 true**。它表示按“排除未完结数据”的策略完整，不表示统计终点到秒等于请求时刻。Answer 必须说明截至 15:20。

## 5. 粒度、保留期与预算

### 5.1 缺省粒度

成交 K 线与标记/指数价格共用 [CandleIntervalSelector](../src/main/java/com/cexpilot/market/series/CandleIntervalSelector.java)：

1. 用户明确指定 interval，原样使用，再做支持能力检查；不自动改粗。
2. 用户未指定时，按数据源支持粒度从细到粗尝试，以对齐后的根数判断，优先不超过 `min(1500, capability.budget())`。
3. 全部超过目标时选最粗可用粒度，仍由 SeriesQueryPolicy 检查总预算与保留期。

1500 是开销目标，不是统一 HTTP 页大小，也不是硬查询上限。当前 K 线候选为 5m / 15m / 1h；不要填 interval=auto。结果 candle_interval 为实际粒度，interval_source 为 automatic / explicit。

OI 不套用 K 线自动策略，缺省 1h，支持 5m / 15m / 30m / 1h / 2h / 4h / 6h / 12h / 1d。taker 固定官方 5m，不能传 interval 或 include_unclosed；其结果同样使用 SeriesMetadata，candle_interval 字段在这里表示统计周期，并非成交 K 线。

### 5.2 数据源能力

Source 提供 SeriesCapability，QueryService 不另维护一张交易所能力表。`budget = pageLimit × maxPages` 用于前置规模判断，查询仍可能因历史页更小、边界重叠或接口缺数而不完整。

| 当前 Source | 代码中的能力声明 | 补充 |
| --- | --- | --- |
| Binance Kline / MarkPrice | 1500 × 4 = 6000 | 三档 CandleInterval |
| OKX Kline / MarkPrice | 300 × 20 = 6000 | 近期接口页上限 300，历史 100；每段分页按实际页大小另计算预算 |
| Binance OI | 500 × 8 = 4000 | 保留期 30 天 |
| OKX OI | 100 × 40 = 4000 | 当前 capability 未声明 retentionDays；不代表无限历史可用 |
| Binance taker | 500 × 20 = 10000 | 固定 5m，保留期 30 天 |

这些是工程策略与当前适配声明，不是对交易所未来接口限制的保证。Source 变化应同步测试和本文。保留期检查针对 requested 起点；对齐后的取数仍由覆盖检查确认，不能把“通过前置检查”当成已拿全数据。

## 6. 分页、游标与标准化

Binance / OKX API 必须经仓库规定代理；OKX 请求保留 User-Agent。参数含义由具体端点适配，不应把一个端点的边界约定复制到所有接口。

- Binance 成交 K 线按起点向后推进，右开范围适配为接口的 endMs-1。Source 检查游标是否推进、页预算是否用尽，并按 openTime 去重排序。
- OKX candles / history-candles 的 `before` 是下界、`after` 是上界；从右侧向过去推进 after。传反可能静默返回空数组，不能只看 HTTP 成功。
- OKX Source 按最近 1440 根范围分出近期段与历史段，分别取数，再按 openTime 合并。用于选择接口的 cutoff 从 Source Clock 读取，这是接口路由基准；业务区间和未收盘判定仍以请求固定时间为准。
- OI 与 taker 某些端点使用 begin/end，按对应 Source 适配；不要替换为 before/after。
- OKX 成交 K 线解析使用数组索引 6 的 volCcy 作为基础币成交量、索引 7 的 volCcyQuote 作为 USDT 成交额，索引 5 是张数，不能混淆。索引 8 confirm 标记完结状态。
- taker Source 在区间两侧外扩一个 5m，并在分页交界保留重叠，再按周期起点去重；外扩受请求时刻与保留期限制。QueryService 用 SeriesRangeFilter 裁回 effectiveRange 后再核对，外扩余量不进入统计。

Source 应返回数据及 abortReason。页数用尽、游标停滞等不能默默当作完整成功。HTTP 重试、页请求、指标节点是不同计数层次，Trace 中区分查看。

## 7. 覆盖核对

[SeriesCoverageValidator](../src/main/java/com/cexpilot/market/series/SeriesCoverageValidator.java) 不发 HTTP，只比对数据的时间位置。流程为：生成网格预期点 → 按完结策略剔除预期未完结点 → 核对实际点 → 检查重复、错位、缺失 → 生成 coverage。数量相同不代表位置正确，少一根再多一根不能抵消。

两种点语义决定“完结”与覆盖终点：

| 语义 | 当前使用场景 | 未完结推断 | 单点覆盖终点 |
| --- | --- | --- | --- |
| PERIOD | K 线、标记/指数价格、taker 周期统计 | t + interval > requestTime | t + interval |
| INSTANT | OI 瞬时采样 | t > requestTime | t |

实际点带 confirmed 时优先按数据源标记判断。即使取数结束时已经收盘，也不能把早先收到的 confirm=0 部分值当成最终值。

| coverage 字段 | 含义 |
| --- | --- |
| expected_count / actual_count | 策略下预期点数 / 通过核对的实际点数 |
| missing_count / missing_open_times | 预期但缺失的位置 |
| unexpected_count / unexpected_open_times | 不在预期网格中的实际位置 |
| closed_part_complete | 无缺失、错位、重复，且无分页中止 |
| range_complete | closed_part_complete 且原请求没有超出 requestTime 的未来部分 |
| contains_unclosed / dropped_unclosed | 结果是否含未完结点 / 是否剔除未完结点 |
| covered_until | PERIOD 为末点结束时间；INSTANT 为末个采样时刻，不能混用 |
| abort_reason | 分页中止原因，有值即不完整 |

`SeriesCoverage` 内部记录 duplicates 和 rangeBeyondNow；当前标准 JSON 不单独输出这两个字段，但它们会影响完整性。缺失与错位时间列表只预览前 20 项，count 表示总量，预览不能代替实际错误总数。

`include_unclosed=true` 允许保留部分周期数据，并披露 contains_unclosed；它不意味着可以取得未来完整数据。“今天全天”在中午请求，原区间终点在未来，range_complete=false；与“今天至今”排除最后未收盘 K 线而已收盘部分齐全是不同情况。

## 8. 区间统计与样本不足

Kline / MarkPrice / OI / Taker Provider 仅在 rangeComplete 时生成 Scalar。否则返回 Omitted：保留 coverage 与窗口，设置 statistics_omitted，不产出 value。序列形态可保留实际通过核对的样本和覆盖状态，但算子在提取 samples 前会检查上游完整性，不把部分样本包装为完整窗口均值。

actual_range 与 observation_seconds 按 Provider 的点语义计算：

- K 线、标记/指数价、taker：首个参与周期起点到末个参与周期终点。
- OI：首个采样时刻到末个采样时刻，不补一个 interval。比如自然日 1h 采样从 00:00 到 23:00，观测跨度为 23 小时，不是 24 小时。

不能让模型从两个时间字符串自行推导年化周期；应引用同一结果的 observation_seconds，并遵守 [聚合指标](聚合指标.md) 中的来源限制。

`funding.rate_settled` 当前只接 `recent_n`，使用 FundingQueryService.queryRecent，按结算时间升序返回，末项最新。它不运行时间窗口网格覆盖校验；requested_count / actual_count / sample_complete 只说明期数。底层 FundingQueryService.query 虽有窗口实现，目录没有对应 binding，Planner 不能使用。“过去一周”不能按假设每 8 小时换成 21 期。

## 9. 定位与修改入口

| 现象 | 优先检查 |
| --- | --- |
| 昨天被当作过去 24h | PLAN 中 time.type、extent 与 metric.shape |
| 日期跨午夜变化 | RequestContext 是否在请求前固定，是否错误调用 resolver 的读 Clock 重载 |
| 查到的窗口比用户要求大 | requested / effective、网格对齐与粒度 |
| 显示“截至现在”但数据滞后 | actual_range、covered_until、dropped_unclosed |
| HTTP 200 但 0 条 | Source 参数、OKX 游标方向、实际接口段、保留期 |
| 条数相同但被判不完整 | missing / unexpected / duplicates / abortReason |
| OI 区间时长差一个周期 | INSTANT 的末点语义及 observation_seconds |

测试入口：`TimeSpecParserTest`、`TimeSpecStrictFieldsTest`、`SeriesQueryPolicyTest`、`SeriesCoverageValidatorTest`、`CandleIntervalSelectorTest`、`CandleAutoIntervalTest`，以及对应 QueryService 和 SourcePagination 测试。时间类测试应固定 Clock，覆盖跨午夜、跨年、时区、网格未对齐、未来范围、confirm 与分页中止。先 `mvn test-compile`，按变更选择直接相关测试；线上时间探针需要明确执行指令。
