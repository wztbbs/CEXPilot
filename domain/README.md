# CEX 领域知识学习导航

这里帮助你理解 CEXPilot 服务的交易业务：先读懂产品和指标，再判断数据能支持什么结论，最后把理解转化为查询、监控和评测能力。工程实现仍以根目录 [README](../README.md) 和 [docs](../docs/) 为准。

首版整理及资料核对日期：**2026-10-27**。交易所规则和数据保留范围会变化，使用具体规则前应重新核对来源。文中“官方事实”“分析假设”“项目约定”是三类不同知识：官方文档解释交易所产品与数据；分析假设需要证据检验；项目约定只描述当前 CEXPilot 的选择。

## 每个 Case 怎么学

1. **先预测**：不展开参考思路，写下预期答案、单位、时间范围，以及不能推出的结论。
2. **再验证**：离线题直接手算；手工查询题由你按需提交给 CEXPilot，保存问题、回答和 traceId。真实行情会变化，核对的是定义、计算和证据链。
3. **查差异**：答案与预期不同时，先分清自己理解错误、数据不足和 Agent 错误。Agent 回答正确不代表已证明市场因果关系。
4. **自己归纳**：用一句话概括规律。隔一两周遮住答案重做，看看能否独立解释。

每篇末尾有 6 个 Case，共 **42 个**，覆盖数值推演、常见误解和能力边界。参考思路放在折叠区域；它们是自查线索，不替代你的解释。

| 标记 | 含义 |
| --- | --- |
| 离线推演 | 使用明确给定的教学数据，不访问线上 |
| 手工查询 | 提供可自行输入的问题；实际结果取决于当时行情与数据覆盖 |
| 能力边界 | 学习合理的澄清、部分回答或能力缺口；不保证请求可执行 |

**本目录所有数值示例均为构造的教学数据，除非明确标注了真实来源。没有运行这些 Case，也没有生成新的线上 trace。** 文中提及的 A1、B4 等是仓库已有回归用例标识，代表题目来源，不代表该用例本轮已通过。

## 当前项目能力速记

- 查询主链只支持 Binance / OKX 的 **USDT 报价、USDT 结算永续合约**。领域文档解释现货、交割和币本位，是为了理解区别；这些产品尚不能通过当前指标 Planner 查询。
- 价格与 K 线、OI、已结算 Funding、盘口等，以 [指标目录](../src/main/resources/metrics/cex-perpetual.yml) 的绑定为准。成交 K 线支持 5m / 15m / 1h；主动买卖当前仅 Binance，固定使用官方 5m 数据。
- Funding 当前是最近 N 期已结算样本；当前未结算费率、预测费率、下次结算时间和指定时间窗口未接入。不能用“最近几期”替代“过去几小时”。
- 当前监控为同所同品种、1～2 个条件的 AND，固定每 5 分钟检查，时间指标使用 5m 粒度。OR 等内容只作为业务知识讲解；不代表已实现。

## 把学习转为工程反馈

发现问题时先保存证据，再判断应更新哪里：概念误解补 Domain；品种、单位或时间错误查指标绑定与数据源；算错查计算节点；无证据归因查回答约束；反复出现的错误再整理成 Eval。

可以在自己的笔记中复制以下模板，不必每道题都新增回归用例：

```text
Case ID / 学习日期：
我的预测与理由：
问题、交易所、产品、单位、窗口与粒度：
回答 / traceId（离线题留空）：
独立复核：输入、公式、结果、数据完整性：
哪些结论成立，哪些仍不能判断：
差异定位：自身理解 / 数据 / Planner / 计算 / Answer / Monitor：
用自己的话总结一句规律：
```

线上排查入口见 [Trace 搭建](../docs/trace搭建.md)。本目录不自动运行线上探针、不创建监控、不发送邮件；回归执行继续遵守仓库 [AGENTS.md](../AGENTS.md) 的约束。
